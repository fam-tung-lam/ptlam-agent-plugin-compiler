# The Analogy Device

This reference owns analogy candidate generation, the mapping gate, the
selection turn, and the analogy's own verification.

## Keep a mapping ledger for every candidate

```text
literal concept -> analogy counterpart -> preserved behavior -> known limit
```

## The complete mapping gate

A candidate passes only when all five hold:

1. Every essential literal concept maps to one stable analogy counterpart.
2. Ownership, direction, order, state, cardinality, lifetime, and causality are
   preserved wherever they matter.
3. No analogy element represents unrelated concepts.
4. Exact facts and constraints remain literal.
5. No material rule requires a misleading mapping, unexplained exception, or
   second metaphor.

## Start from the domain the learner supplied

Treat a learner-supplied domain as the first candidate. Use it when it passes
the gate.

When it fails, name the material mismatch and offer passing alternatives. Never
replace a supplied domain silently.

## Generate candidates when no supplied domain passes

Generate several candidates internally. Prefer an everyday domain the learner
can picture, one coherent world, strong relationship fidelity, broad coverage,
and low explanation cost.

These familiar domains are starting points, not defaults:

| Concept pattern                    | Possible analogy domain          |
| ---------------------------------- | -------------------------------- |
| Ordered sequential work            | Recipe or assembly line          |
| Fast storage and retrieval         | Library or filing cabinet        |
| Broadcasting to unknown listeners  | Radio station or newsletter      |
| Complexity behind a simple surface | Restaurant menu                  |
| Concurrent work                    | Multiple cooks in one kitchen    |
| Agreed communication rules         | Introductions or phone etiquette |
| Adjustment from observed output    | Thermostat                       |
| Work distributed across resources  | Traffic control                  |

## Add a selection turn only when the choice is the learner's

Use the strongest passing candidate on your own.

Open a selection turn when the learner asks to choose, rejects the current
analogy, or the candidates expose meaningfully different teaching trade-offs.

In that turn, present at most three passing candidates. Give each a short domain
name, one sentence about the structural similarity, and the material teaching
trade-off. Mark the strongest **(Recommended)**, ask which to use, and wait.
Never offer a candidate that failed the gate.

If no coherent candidate passes, ask the learner to narrow the learning goal
instead of forcing a weak analogy.

## Verify the analogy

Reapply the mapping gate to the drafted explanation. Then confirm that:

- the story demonstrates the mechanism instead of decorating it;
- exact facts stayed literal, in the map or in the limitations; and
- the learner can reconstruct the literal model from the map alone, without the
  story.

When drafting reveals a failed mapping, do not return it. For an analogy you
selected on your own, use the next strongest passing candidate. For a
learner-supplied one, follow the supplied-domain rule above.

## Finish

Finish when one analogy passes the gate, every learner-supplied domain is
honored or rejected for a named mismatch, any required learner choice is
settled, and these verification checks hold.
